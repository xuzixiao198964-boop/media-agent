## 1. 需求背景

Media Agent 项目原本的认证系统较为复杂，包含：
- 注册时需要邮箱、手机号双重验证
- 登录时有密码登录和验证码登录两种方式
- 图形验证码保护
- 复杂的密码策略

在实际使用中，这些功能对于内部使用或测试环境显得过于繁琐，需要简化认证流程。

## 2. 需求目标

### 2.1 主要目标
1. 简化用户注册流程，移除不必要的验证步骤
2. 简化用户登录流程，提供更直接的访问方式
3. 保持系统安全性在可接受范围内

### 2.2 具体需求

#### 2.2.1 注册功能简化
- [x] **移除邮箱注册验证**
  - 移除注册时的邮箱输入框
  - 移除邮箱验证码发送和验证
  - 邮箱字段设为可选（空字符串）

- [x] **移除手机号注册验证**
  - 移除注册时的手机号输入框
  - 移除手机验证码发送和验证
  - 手机字段设为可选（NULL）

- [x] **移除图形验证码**
  - 移除注册时的图形验证码
  - 移除验证码图片加载逻辑

- [x] **简化注册表单**
  - 只保留用户名和密码字段
  - 简化前端UI，移除不必要的元素
  - 更新提示信息

#### 2.2.2 登录功能简化
- [x] **移除验证码登录选项**
  - 移除登录页面的验证码登录选项卡
  - 移除邮箱/手机验证码登录逻辑
  - 只保留密码登录方式

- [x] **移除登录失败验证码**
  - 移除连续登录失败后的图形验证码要求
  - 简化错误处理逻辑

- [x] **简化登录表单**
  - 只保留用户名/邮箱和密码字段
  - 移除验证码相关UI元素

- `/auth/login/send-code` (已注释)

## 5. 风险与注意事项

### 5.1 安全风险
1. **暴力破解风险增加**: 移除了验证码保护，增加了暴力破解的可能性
   - **缓解措施**: 建议添加登录失败限制、IP限制等

2. **密码重置问题**: 忘记密码功能目前仍需要邮箱和手机验证
   - **影响**: 新注册的用户（没有邮箱和手机）无法使用忘记密码功能
   - **建议**: 可以修改忘记密码逻辑，或暂时禁用该功能

### 5.2 兼容性问题
1. **现有用户**: 现有用户可以通过用户名登录，邮箱字段可能为空
2. **第三方集成**: 如果其他系统依赖邮箱或手机验证，可能需要调整
3. **数据一致性**: 确保User表的email字段允许空值

### 5.3 性能影响
1. **正面影响**: 减少了验证码生成和验证的开销
2. **负面影响**: 无显著性能影响
