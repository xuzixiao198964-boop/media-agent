## 1. 项目背景与目标

### 1.1 背景

现有 Media Agent 系统已实现「资讯 → 短视频 → 发布」的完整链路，支持资讯口播、文案生成、TTS 配音、VideoRetalk 口型同步等能力。

本需求在此基础上扩展**小说故事影片生成**能力：将 `ai-novel-agent` 系统发布的长篇小说按章节拆解，生成高质量的连续剧式故事影片，要求跨章节声音一致、画面连贯、支持人工审核与返工。

### 1.2 目标

1. 从 `ai-novel-agent` 的已发布小说中选取作品，按章节生成故事影片
2. 每章视频时长 3-10 分钟，具有故事性和观赏性
3. 多角色配音，不同角色使用不同声线，跨章节一致
4. AI 生成场景画面（图片 + 动态视频），视觉风格统一
5. **双重审核机制**：脚本审核 + 成片审核，不通过可驳回重做
6. 支持增量重做（只重做有问题的部分，不浪费已通过内容）

### 1.3 与现有系统的关系

本需求为**追加扩展**，不替换现有短视频生成能力。现有的资讯口播、文案视频、TTS、FFmpeg 等基础能力继续保留并复用。

## 2. 系统架构

### 2.1 整体流程

```
①导入小说（从 ai-novel-agent 拉取）
    ↓
②AI 拆章 → 角色识别 → 结构化分镜脚本生成
    ↓
③【脚本审核】── 不通过 → AI 根据审核意见重写 → 回到③
    ↓ 通过
④多角色配音 + AI 场景画面生成 + BGM 匹配
    ↓
⑤FFmpeg 合成章节成片
    ↓
⑥【成片审核】── 不通过 → 定位问题项 → 增量重做 → 回到⑥
    ↓ 通过
⑦入库 / 发布
```

## 4. 分镜脚本格式

### 4.1 AI 生成的结构化脚本

每章原文经 DeepSeek 拆解后，生成如下 JSON 结构：

```json
{
  "chapter_no": 1,
  "title": "第一回 甄士隐梦幻识通灵",
  "summary": "本章引出贾雨村和甄士隐的初遇，为全书埋下伏笔。",
  "estimated_duration_sec": 240,
  "scenes": [
    {
      "scene_id": 1,
      "type": "narration",
      "speaker": "narrator",
      "text": "话说贾雨村在扬州城中寄居，日日以诗酒自遣。",
      "visual_prompt": "古代扬州城街景，黄昏时分，一个落魄书生独自在酒馆临窗饮酒，远处是繁华的街市",
      "mood": "melancholy",
      "duration_hint": 8
    },
    {
      "scene_id": 2,
      "type": "dialogue",
      "speaker": "贾雨村",
      "text": "玉在匮中求善价，钗于奁内待时飞。",
      "visual_prompt": "书生站在窗前仰望明月，衣衫微旧但眼神坚定",
      "mood": "ambitious",
      "duration_hint": 6
    },
    {
      "scene_id": 3,
      "type": "narration",
      "speaker": "narrator",
      "text": "甄士隐在隔壁花园散步，忽然听到此联，不禁击节叹赏。",
      "visual_prompt": "一位中年儒商在精致的私家花园中漫步，月光洒在假山和池塘上",
      "mood": "curious",
      "duration_hint": 7
    },
    {
      "scene_id": 4,
      "type": "dialogue",
      "speaker": "甄士隐",
      "text": "兄何不去求取功名，以展平生之志？",
      "visual_prompt": "两人在花园石桌旁对坐，月下品茶",
      "mood": "warm",
      "duration_hint": 5
    },
    {
      "scene_id": 5,
      "type": "transition",
      "speaker": null,
      "text": null,
      "visual_prompt": "画面淡出，月亮升至中天，时间流逝",
      "mood": "neutral",
      "duration_hint": 2
    }
  ]
}
```

### 4.2 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| scene_id | 是 | 场景序号，从 1 开始 |
| type | 是 | narration（旁白）/ dialogue（对话）/ transition（过渡转场）/ monologue（独白） |
| speaker | 是 | 说话人。narrator = 旁白；角色名须与 NovelCharacter.name 完全一致；transition 为 null |
| text | 否 | 台词/旁白文本。transition 可为 null |
| visual_prompt | 是 | 场景画面描述，用于 AI 图片/视频生成 |
| mood | 是 | 情绪标签，用于 TTS 语气控制和 BGM 匹配 |
| duration_hint | 是 | 建议时长（秒），控制节奏 |

### 4.3 角色一致性约束

- AI 生成脚本时，所有 speaker 必须映射到 `NovelCharacter` 表中已有的角色
- 新出现的说话人，AI 应在脚本中标注，系统提示用户为其分配声线
- 同一角色在所有章节中使用完全相同的 speaker 名称

## 5. 审核流程

### 5.1 脚本审核（第一轮）

**触发时机**：AI 完成分镜脚本生成后。

**审核内容**：
1. 旁白与对话的拆分是否合理
2. 角色归属是否正确（谁说了哪句话）
3. 画面描述是否与文意一致
4. 整体节奏和时长是否合适
5. 情绪标注是否恰当

**审核操作**：
- **通过**：整章脚本进入配音+画面生成阶段
- **驳回 + 整体意见**：AI 根据意见重新生成整章脚本
- **逐场景修改**：用户直接编辑某个 scene 的文本或画面描述（不触发 AI 重写）

**驳回重写规则**：
- AI 重写时注入用户的审核意见作为约束
- 保留用户已手动修改过的 scene（标记为 `user_edited`），仅重写未编辑的部分
- 重写后回到 `draft` 状态，需再次审核

### 5.2 成片审核（第二轮）

**触发时机**：章节成片合成完成后。

**审核维度（4 项）**：

| 审核项 | 检查内容 | 不通过时的处理 |
|--------|---------|---------------|
| 画面 | 场景画面是否与脚本描述一致、风格是否统一、有无瑕疵 | 标记 scene_id → 仅重新生成该场景画面 |
| 配音 | 角色声线是否正确、语气是否合适、有无吞字错读 | 标记 scene_id → 仅重新合成该段 TTS |
| BGM | 背景音乐是否与情绪匹配、音量是否合适 | 更换 BGM 或调整音量 → 重新混音 |
| 整体 | 音画同步是否正确、字幕有无错误、节奏是否合理 | 调整时间轴参数 → 重新合成 |

**增量重做规则**：
- 只重做被驳回的部分，通过的素材直接复用
- 替换素材后重新合成（FFmpeg），不需要重走全流程
- 生成新成片后再次进入成片审核

### 5.3 章节状态机

```
                     ┌─────────────────────────────┐
                     │                             │
raw_text ──→ script_draft ──→ script_reviewing ─┬──→ script_approved
                  ↑                             │       │
                  └──── script_rejected ←───────┘       │

                                              generating_assets
                                                        │
                                                        ↓
                                                  compositing
                                                        │
                                                        ↓

                     │         │                        │

                     │    │         │                   │
                     │ approved  rejected               │
```

## 6. 多角色配音系统

### 6.1 声线管理

每个小说项目维护独立的角色-声线映射表，确保跨章节一致。

**声线来源**：
- **Fish Audio 预设声线**：从 Fish Audio 声线库选择（男声/女声/老年/少年等）
- **声音克隆**：用户上传参考音频 → 调用 Fish Audio 克隆 API → 生成专属声线 model_id
- **系统预设旁白**：腾讯云 TTS / Edge TTS / OpenAI TTS 作为旁白备选

**声线锁定机制**：
- 项目创建时分配声线，后续所有章节自动继承
- 声线变更需用户确认，且可选择"重新生成已有章节的配音"

### 6.2 配音合成流程

```
approved_script.scenes[]
    │
    ├── scene[type=narration]  → narrator_voice_id  → Fish Audio TTS → audio_01.mp3
    ├── scene[type=dialogue]   → character.voice_id  → Fish Audio TTS → audio_02.mp3
    ├── scene[type=transition] → (静音或环境音)       → FFmpeg 生成    → silence_03.mp3
    └── scene[type=dialogue]   → character.voice_id  → Fish Audio TTS → audio_04.mp3
    │
    ▼ FFmpeg concat + crossfade（场景间 0.3s 渐变）
    chapter_N_voice.mp3
    │
    ▼ 叠加 BGM（根据 mood 自动匹配或用户指定）
    chapter_N_final_audio.mp3
```

### 6.3 Fish Audio API 调用规范

| 参数 | 说明 |
|------|------|
| model_id | 声线 ID（角色表中的 voice_id） |
| text | 台词文本 |
| format | mp3 |
| 情绪控制 | 通过 prompt 或 SSML 控制语气（如"用悲伤的语气说"） |

## 7. AI 场景画面生成

### 7.1 两步生成策略

采用「先生图 → 审核 → 再生视频」的两步策略，确保画面质量可控：

```
scene.visual_prompt + project.visual_style + character.appearance
    │
    ▼ 第一步：生成静态场景图
    硅基流动 API（Flux 模型） → scene_N.png
    │
    ▼ 用户可在成片审核时检查图片
    │
    ▼ 第二步：图片动态化
    可灵 AI（图生视频） → scene_N.mp4（5-8秒）
```

### 7.2 视觉一致性保障

| 手段 | 说明 |
|------|------|
| 全局风格前缀 | 每个图片/视频 prompt 前拼接 `project.visual_style`（如"中国工笔画风格，暖色调，电影质感"） |
| 角色外貌注入 | 涉及角色的场景，prompt 中注入 `character.appearance`（如"林黛玉：瓜子脸，柳叶眉，身穿淡绿色衣裙"） |
| 固定负面提示词 | 统一的 negative_prompt 排除常见瑕疵（如"变形、模糊、现代元素"） |

### 7.3 API 调用

#### 硅基流动（图片生成）

| 参数 | 说明 |
|------|------|
| model | Flux.1-schnell 或 SDXL |
| prompt | visual_style + appearance + scene.visual_prompt |
| size | 1920x1080（横屏）或 1080x1920（竖屏） |
| 预估成本 | ￥0.01-0.03/张 |

#### 可灵 AI（视频生成）

| 参数 | 说明 |
|------|------|
| 输入 | 场景图片 + 运镜描述 |
| 时长 | 5 秒 |
| 分辨率 | 1080p |
| 预估成本 | ￥0.3-2/条 |

## 8. 背景音乐系统

### 8.1 BGM 库

系统维护一个按情绪分类的 BGM 库，支持：
- **系统预置**：从免版权网站预先下载的 BGM（Pixabay Music、Mixkit、Free Music Archive）
- **用户上传**：用户自行上传 BGM 文件
- **后期扩展**：接入 Suno AI 按场景自动生成 BGM

### 8.2 情绪分类标签

| 标签 | 中文 | 适用场景 |
|------|------|---------|
| epic | 史诗 | 战斗、宏大场面、高潮 |
| sad | 悲伤 | 离别、死亡、回忆 |
| romantic | 浪漫 | 爱情、相遇、温馨 |
| tense | 紧张 | 悬疑、追逐、危机 |
| peaceful | 宁静 | 日常、风景、休憩 |
| comedy | 欢快 | 搞笑、轻松、庆祝 |
| mysterious | 神秘 | 玄幻、梦境、未知 |
| heroic | 英勇 | 觉醒、逆转、英雄时刻 |

### 8.3 BGM 匹配规则

1. AI 生成分镜脚本时，每个 scene 标注 `mood`
2. 系统统计本章各 mood 的占比，选择最匹配的 BGM
3. 用户可在成片审核时手动更换 BGM 或调整音量
4. 同一小说项目可设置默认 BGM，章节级别可覆盖

## 9. 成片合成

### 9.1 合成流程

```
各 scene 的视频/图片素材
    +
各 scene 的音频文件
    +
字幕文件（SRT）
    +
BGM
    +
片头模板（可选：书名 + 第 N 章 + 章节标题）
    +
片尾模板（可选：下章预告）
    │
    ▼ FFmpeg 合成
    chapter_N_final.mp4
```

### 9.2 合成参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 输出分辨率 | 1080x1920（竖屏）或 1920x1080（横屏） | 用户可选 |
| 视频编码 | H.264 | 兼容性最好 |
| 音频编码 | AAC 128kbps | 标准质量 |
| 场景间转场 | 1s 淡入淡出 | 可配置 |
| 字幕样式 | 白色描边，底部居中 | 可配置字体、大小、颜色 |
| BGM 音量 | 0.15（配音场景）/ 0.4（纯画面场景） | 自动调节 |
| 片头时长 | 3-5s | 书名+章节信息 |

## 12. 非功能性需求

### 12.1 性能

- 单章节脚本生成：< 30 秒
- 单 scene TTS 合成：< 10 秒
- 单 scene 图片生成：< 15 秒
- 单 scene 视频生成：< 120 秒
- 整章合成（FFmpeg）：< 60 秒
- 单章端到端（无审核等待）：< 30 分钟

### 12.2 可靠性

- API 调用失败自动重试 3 次
- 每个 scene 的素材独立生成，单个失败不影响其他
- 所有中间产物（音频、图片、视频）持久化存储，避免重复生成

### 12.3 存储

- 单章素材：约 200-500 MB（音频 + 图片 + 视频片段 + 成片）
- 整本小说（30 章）：约 6-15 GB
- 定期清理策略：成片审核通过后，可选删除中间素材
